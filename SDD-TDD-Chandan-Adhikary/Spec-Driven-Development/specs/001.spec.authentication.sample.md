# Feature Specification: 001 — User Authentication & RBAC

**Spec ID:** SPEC-001  
**Version:** 1.0.0-APPROVED  
**Status:** Approved for Implementation  
**Traceability:** PRD Section 3.1 | ADR-002  

## 1. Feature Overview
Provide secure multi-tenant authentication with role-based access control (RBAC) supporting School Admins, Teachers, Students, and Parents.

## 2. Domain Invariants & Rules
- Passwords must meet minimum entropy criteria (>= 12 chars, mixed case, symbol, digit).
- Session tokens must use secure, httpOnly, SameSite=Strict cookies with 15-minute access token expiry and rotating refresh tokens.
- Account lockout after 5 consecutive failed authentication attempts for 15 minutes.

## 3. API Contract
- `POST /api/v1/auth/login` -> `{ email, password, tenant_id }`
- `POST /api/v1/auth/refresh` -> `{ refresh_token }`
- `POST /api/v1/auth/logout` -> `{}`

## 4. Acceptance Criteria & Test Scenarios
- [ ] **AC-AUTH-001:** Valid credentials for active user return 200 with JWT session tokens and user profile payload.
- [ ] **AC-AUTH-002:** Invalid password returns 401 with generic error message ('Invalid credentials') without timing leaks.
- [ ] **AC-AUTH-003:** Five failed attempts lock account and log security alert in audit log.
- [ ] **AC-AUTH-004:** Inactive or deleted tenant users are rejected with 403 Forbidden.
