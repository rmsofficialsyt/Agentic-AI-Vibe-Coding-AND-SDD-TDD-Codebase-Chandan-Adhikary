## Purpose

Short cycle discovery and prototype plan for Vibe Coding.

## Agent read trigger

**MUST** read or consult this file: Before experiments, major pivots and production promotion.

## Normative sections and rules

### 1. Problem and outcome

- **MUST** — Record problem, users, pain points, success indicators, assumptions and intended prototype outcome.

### 2. Scope

- **MUST** — List MVP capabilities, explicit non-goals, boundaries and what remains unvalidated.

### 3. Prototype contract

- **MUST** — Choose initial user flows, UI direction, constraints, stack assumptions and demo acceptance observations.

### 4. Milestones

- **MUST** — Sequence discovery, prototype, evaluation, formalization, testing, review and production promotion.

### 5. Experiment controls

- **MUST** — Keep prototype work separate from approved production scope; avoid sensitive data and irreversible integrations.

### 6. Iteration evidence

- **SHOULD** — Document screenshots, feedback, rejected hypotheses and next actions.

### 7. Approval

- **MUST** — Obtain explicit approval before making exploratory features part of the production baseline.

## Evidence and change control

- **MUST** record owner, revision/date, relevant approval reference, and traceable evidence in the applicable project instantiation.
- **MUST** route changes to process rules through `docs/guideline-CHANGELOG.md` and formal baseline revision; route feature behavior through approved versioned specs and `docs/CHANGELOG.md`.
- **SHOULD** keep links to canonical artifacts instead of duplicating definitions.

## Vibe Coding interpretation

- **MAY** use provisional decisions in an isolated prototype, clearly marked `DRAFT`; **MUST** formalize and approve production-bound behavior before shipping.
