# Prd

> **Document class:** Living feature/specification  
> **Framework:** Vibe Coding  
> **Guideline baseline:** 1.0.0  
> **Status:** Template; project-specific content requires review  

## Purpose

Product requirements and measurable user outcomes.

## Agent read trigger

**MUST** read or consult this file: Discovery; prior to feature approval and acceptance evaluation.

## Normative sections and rules

### 1. Problem and audience

- **MUST** — Define customer problem, user/persona, context and jobs-to-be-done.

### 2. Goals

- **MUST** — Define product outcomes, success metrics and measurable targets where known.

### 3. Scope

- **MUST** — Distinguish in-scope, out-of-scope, future ideas and non-goals.

### 4. Requirements

- **MUST** — Assign stable IDs to functional requirements; describe observable behavior and business rules.

### 5. Non-functional

- **MUST** — Specify applicable security, privacy, reliability, accessibility, performance, availability and cost constraints.

### 6. Journeys

- **MUST** — Cover critical user paths plus loading, empty, failure and recovery states.

### 7. Acceptance

- **MUST** — Link each requirement to objective pass/fail criteria and proposed verification evidence.

### 8. Dependencies

- **MUST** — Record integration, platform, organizational and timeline constraints.

### 9. Approval

- **MUST** — Include document owner, version, decision status and sign-off reference.

### 10. Prioritization

- **SHOULD** — Use clear MVP versus later-release classification.

### 11. Research

- **MAY** — Include hypotheses, competitor references and discovery interviews.

## Evidence and change control

- **MUST** record owner, revision/date, relevant approval reference, and traceable evidence in the applicable project instantiation.
- **MUST** route changes to process rules through `docs/guideline-CHANGELOG.md` and formal baseline revision; route feature behavior through approved versioned specs and `docs/CHANGELOG.md`.
- **SHOULD** keep links to canonical artifacts instead of duplicating definitions.

## Vibe Coding interpretation

- **MAY** use provisional decisions in an isolated prototype, clearly marked `DRAFT`; **MUST** formalize and approve production-bound behavior before shipping.
