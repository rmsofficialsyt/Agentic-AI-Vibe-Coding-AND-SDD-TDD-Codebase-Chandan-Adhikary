01-Setup-Project
================

Purpose: Bootstrap Vibe-Coding in a new or existing project with verified slash commands, terminal activation, docs, and living vibe baseline.
Read trigger: MUST read immediately before setting up or copying this framework into a project.
Applicability: Vibe-Coding

Prerequisites:
- Copy framework files to the **workspace/git root** (IDEs discover `.agents/` at the repo root, not nested subfolders).
- Read `AGENTS.md`, `docs/INDEX.md`, and `LICENSE.md`.
- **MANDATORY PRE-CODEBASE GATE:** Verify and activate custom slash commands in both the AI Chat dropdown (type `/` to see all 16 `*-ca-agent` commands) and Terminal CLI (`ls .agents/commands/*-ca-agent.md`) BEFORE creating any application directories.
- **MANDATORY LOGS DIRECTORY:** Ensure `logs/` folder exists with `logs/.gitkeep` for development logs (`*.log`). Verify `logs/*.log` is ignored in `.gitignore`.
- **PRE-PROMPTING DOMAIN & SYSTEM DESIGN GATE:** Establish thorough domain knowledge and system design before issuing Prompt 1. If not manually prepared, ask the AI agent to explain and formulate system design during planning, and integrate it into Prompt 1.

Commands & Skills:
- Commands: `/plan-ca-agent`, `/dashboard-ca-agent`, `/task-ca-agent`
- Skills: Core repo skills (`task-planner`, `code-reviewer`). Third-party skills are developer choice installed on-demand from GitHub.

Procedure:
1. Custom Slash Commands & Terminal Activation (Step 0):
   - Open project root in IDE.
   - Type `/` in chat: confirm all 16 `*-ca-agent` commands appear with descriptions.
   - Run terminal check: confirm `.agents/commands/` files exist and are readable.
2. Define Product & Living Baseline:
   - Populate `docs/product.md`, `docs/prd.md` (including Section 5 Technical Requirements), `docs/system-architecture.md`, and `docs/design.md`.
   - Maintain `LICENSE.md` and `.github/SECURITY.md`.
3. 5-Step Cyclic Prompt Loop:
   - Step 1: Reading Prompt (Ingest vibe, user persona, styling intent).
   - Step 2: Analysis Prompt & Plan (Deconstruct UI flows and dependencies).
   - Step 3: Check/Recheck `docs/` and `playbooks/`.
   - Step 4: Review `*.md` Guidelines.
   - Step 5: Overwrite Full Guidelines before writing implementation code.
4. Verify Setup:
   - Launch In-IDE Dashboard: `/dashboard-ca-agent` (portable across all resolutions with current running task and HEAD commit pinned on top).

Required output:
- Active IDE slash commands in `/` dropdown, clean docs, and initialized `docs/product.md` + `docs/prd.md`.
