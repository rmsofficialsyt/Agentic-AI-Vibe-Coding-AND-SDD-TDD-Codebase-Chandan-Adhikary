03-Features-Development
========================

Purpose: Author, refine, and evolve feature specifications in `docs/features/` with Flat vs Modular inquiry and complexity tiers.
Read trigger: MUST read before authoring new features or updating existing features in Vibe-Coding.
Applicability: Vibe-Coding

Prerequisites:
- Read `docs/features/README.md` and `docs/product.md`.

Commands & Skills:
- Commands: `/plan-ca-agent`, `/task-ca-agent`, `/implement-ca-agent`, `/review-ca-agent`
- Skills: Core repo skills (`task-planner`, `code-reviewer`).

Procedure:
1. Format Inquiry & Complexity Categorization:
   - **MANDATORY DEVELOPER PROMPT:** Always ask the developer:
     "Would you prefer this specification in Flat format (docs/features/NNN-name.md) or Modular format (docs/features/NNN-name/{feature,acceptance,test-plan}.md)?"
   - If developer defers, decide by complexity tier:
     - Tier 1 (Easy, 1-2 files): Flat format.
     - Tier 2 (Intermediate, 3-6 files): Flat format.
     - Tier 3 (Hard/Complex, 7+ files): Modular format.
2. Intake & Feature Spec Authoring:
   - Copy from `docs/features/FEATURE-TEMPLATE.md`.
   - Assign feature ID and sensory acceptance criteria.
3. Step-by-Step Implementation & Frontend-First Verification:
   - Implement one feature at a time following staged web progression.
   - Build frontend first; verify live in browser with `/run-ca-agent`; only then proceed to backend persistence and security.
   - Maintain execution and test logs in `logs/` (`logs/*.log`), updating `docs/task.md` upon completion.
