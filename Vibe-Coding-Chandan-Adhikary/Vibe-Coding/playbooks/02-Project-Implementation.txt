02-Project-Implementation
=========================

Purpose: Repeatable, evidence-based execution playbook.
Read trigger: MUST read immediately before performing this activity.
Applicability: Vibe Coding

Prerequisites:
- MUST identify project, current guideline baseline, task owner and authorized scope.
- MUST verify latest approved specification when doing production work.

Procedure:
1. Authority — MUST: Confirm plan, requirements/spec version and architecture.
2. Decompose — MUST: Prepare scoped tasks and file ownership.
3. Test first — MUST: For SDD write tests that fail for intended reasons before code.
4. Build and report — MUST: Implement in increments; run gates and record evidence.

Required output:
- MUST record task/spec version, owner, inputs, evidence, open risks, approvals and next authorized action.
- MUST stop at missing approval, unresolved policy conflict, unsafe credentials or failed release-blocking gates.
- SHOULD link canonical docs rather than copying rule text.

Change policy:
- MUST revise this playbook only through guideline version, reason, date, approval and guideline changelog.
