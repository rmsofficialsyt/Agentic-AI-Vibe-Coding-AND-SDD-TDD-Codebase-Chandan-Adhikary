02-Project-Implementation
==========================

Purpose: Execute Vibe-Coding feature implementation step-by-step with rapid sensory feedback loops.
Read trigger: MUST read before writing UI or application code in Vibe-Coding.
Applicability: Vibe-Coding

Prerequisites:
- Feature spec drafted in `docs/features/`.
- Task identified in `docs/task.md`.
- **SPEC PACING RULE:** Step-by-step spec development. Build, test, sensory check, and update docs for one feature before moving to the next.
- **STAGED WEB DEVELOPMENT (Frontend-First Verification):** For web applications, do NOT build all features at once. First build and verify the frontend during a live demo run (`/run-ca-agent`). Only after visual and functional approval on screen, implement backend APIs, database persistence, and security controls.
- **MANDATORY DEVELOPMENT LOGGING:** Pipe and maintain test executions, build logs, and runtime outputs inside dedicated log files in `logs/` (`logs/test.log`, `logs/dev.log`, `logs/server.log`, `logs/error.log`). Never scatter raw logs in project root.

Commands & Skills:
- Commands: `/plan-ca-agent`, `/implement-ca-agent`, `/run-ca-agent`, `/task-ca-agent`, `/review-ca-agent`, `/verify-ca-agent`
- Skills: Core repo skills (`task-planner`, `code-reviewer`).

Procedure:
1. The 5-Step Cyclic Prompt Loop:
   - Step 1 (Read Prompt): Ingest UI/feature request.
   - Step 2 (Analyze & Plan): Run `/plan-ca-agent` for layout and stack deconstruction.
   - Step 3 (Check Docs/Playbooks): Check `docs/design.md` and `docs/system-architecture.md`.
   - Step 4 (Review Guidelines): Determine guideline updates.
   - Step 5 (Overwrite Guidelines): Overwrite living guidelines with real project parameters before implementation.
2. Implement & Run:
   - Run `/implement-ca-agent` to scaffold layout and components within allowed files.
   - Run `/run-ca-agent` to launch local dev server and verify in browser.
3. Fluid Feedback Loops:
   - Use `/task-ca-agent` and `/review-ca-agent` for rapid iterative polish.
   - Verify mobile/tablet/desktop responsive layouts across viewports.
4. Verify & Log:
   - Update `docs/task.md` (mark current task DONE, float next running task to top in dashboard).
   - Log any UI glitches in `docs/error-tracker.md`.

Required output:
- Working live application, passing tests, clean commit with HEAD commit on top in dashboard.
